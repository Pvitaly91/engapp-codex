## Самостійна навчальна мета

- Causative B1–B2: прочитати базовий have/get + object + V3 через ролі й утворити прості питання/заперечення, не сплутати зі звичайним perfect. Складні ситуації результату та виконавця — коротке point-level поглиблення, не повтор C1 сусіда.
- Get-Passive B1: утворити get/gets/got + V3, звичайне Simple питання/заперечення та розрізнити подієвий пасив, get + object + V3 і зміну стану. Один continuing B2 block з часовими формами лишається B2; hero не підвищується.
- Impersonal B2–C1: вибрати один із двох reporting-каркасів і незалежно зберегти час повідомлення та повідомлюваної події. Складні active/passive infinitive, заперечення й джерело не дублюють увесь прийнятий C1/C2 урок; є точні посилання на поглиблення.

### Приклади Causative: конкретні рішення

- Не переписано дванадцять коректних services/examples заради новизни; переклад і роль уточнені там, де це було необхідно.
- `I had my car to repair.` збережено як іншу have-модель у comparison, не як помилку каузативу.
- `I had repaired my car.` розгорнуто через `before the trip began`, щоб visible basic мав минулу опору.
- `I had cut my hair.` доповнено `before the party`, щоб порівняння не виглядало як безконтекстний вирок.
- `I had repaired my car yesterday.` згадано у comparison warning з явною умовою пізнішого минулого моменту. Yesterday не робить Past Perfect автоматично неграматичним.
- У mistakes-grid ці граматичні приклади не залишено red wrong. Нові V3 та do-support errors самостійні й зберігають об’єкт/час/учасників.

## Basic/detail і component mapping

Усе, що необхідне для виконання базової практики, переклади, короткі застереження й посилання visible basic. Details містять додаткове пояснення разом з прикладами та розбором; не створені за квотою і не залежать від runtime кількості слів.

| Detail key | Власник | Семантична причина лишити disclosure |
|---|---|---|
| causative-person-or-object | causative-services `/sections/1` | Три каркаси з окремим виконавцем або річчю; пояснення керування та ролей, не додатковий одиночний приклад. |
| causative-perfect-and-result | causative-tenses `/items/3` | Perfect каузативу з двома had та обмеження inference у get something done як досягненні результату. Основний service/no-price/counterexample уже basic. |
| get-event-versus-duration | get-tenses `/sections/3` | Event-versus-state до теперішньої точки, got/gotten і тривалість; не просто перелік альтернатив. |
| impersonal-extended-infinitives | impersonal-infinitives `/sections/1` | Раніший процес/пасивний результат/майбутня межа, окремо час та role subject. Це поглиблення понад компактний B2 basic. |
| impersonal-negative-scope | impersonal-more-forms `/items/7` | Not known проти known not та різні умови істинності з повним перекладом обох речень. |

Дозволені component types: hero, forms-grid, usage-panels, comparison-table, mistakes-grid, summary-list, navigation-chips, practice-set. Usage groups мають explicit labels/accents, правила і bilingual examples; не анонімні речення-картки. Forms titles містять формулу, а subtitles — EN/UK annotations без прихованих альтернатив. Таблиці не складають всі приклади в note. Corrections мають `wrong_en/wrong_ua/right_en/right_ua/note`, як чинний M52 supported format. Немає нових view/CSS/JS/grader.

## Практика та різниця з банком

Власні 18 завдань нові, не скопійовані з accepted C1/C2 сусідів. Кожна сторінка має 2 selects, 2 choices, 2 inputs. Один input має два способи відповіді — manual і tokens, а не подвійну статистику.

- Causative: V3/do-support; організатор/виконавець; causative-vs-Past-Perfect; виразний сервісний контекст для двох inputs.
- Get: did/didn't + get; позитивна подія; get-passive-vs-get-object-V3; question/negative input прямо задають get-модель і не оголошують be-passive неграматичним.
- Impersonal: раніша й одночасна подія; майбутній expect; not-known scope; input It… та subject… з явним reporting verb/часом.

У choices повний точний переклад English stimulus показується після Check, коли він розкривав би відповідь. Відразу видно достатній UK контекст. Select variants короткі; input slash-banks перемішані, без готової відповіді у placeholder. Aliases скорочень задаються скінченно; глобальний normalizer не змінюється. До freeze завершено незалежний main review і перевірку actual answer-engine canonical/accepted/token instances та bindings `before/after`. Live взаємодія після apply документується окремо.

Окремий bank widget = 15 відібраних питань, не частина 18 власних tasks: 5 Causative + 5 Get + 5 Impersonal. З незалежного bank audit: 12 old reused, 3 new Get supplement; немає нового банку для кожної сторінки. Main review затвердив мінімальний versioned supplement і його exact write scope. Frozen master використовує exact seeder names та reviewed finite intro; старі question payloads не переписуються. Source зафіксовано до apply; фактичні DB/hash/live результати не заявляються цим редакційним mapping.
