# Контракт майбутнього пакета «коротко + деталі»

M25 додає лише render-only готовність. Жоден справжній урок не отримує
короткої редакції або нового disclosure у цьому етапі. Всі нинішні тексти
залишаються повним видимим основним вмістом; схема БД не змінюється.

## Що передає автор наступного погодженого пакета

- Стабільний ключ уроку/секції та наявний заголовок; авторський номер,
  якщо він є. Не замінювати існуючі IDs, UUID, `block-<id>` та self-check anchors.
- Готовий авторський короткий матеріал `main`, без автоматичного вибору
  першого абзацу, генерації скорочення чи перекладу.
- Перелік `detail_references`: існуючі IDs незмінних детальних секцій у
  потрібному авторському порядку. Посилання не містять `#`; кожен ID
  має починатися латинською літерою, решта — літери/цифри/`_.:-`.
- Точна редакція `source_revision`: SHA-256 початкового повного дозволеного
  HTML, який передає чинний renderer. Це прив’язка до конкретного джерела,
  а не до тексту, витягнутого з уже скороченого результату.
- Явне погодження пакета та перелік цільових уроків. Сам факт наявності
  довгого тексту, поля в JSON або технічного fixture не є дозволом скорочувати урок.

Вихідні authored masters/definitions залишаються авторитетним джерелом.
Наступний етап окремо визначає versioned формат зберігання погодженого пакета;
M25 не додає таблиць, фонового apply чи автоматичних HTTP/startup hooks.

## Рендеринг

`<x-theory-section>` отримує `sectionKey`, `title`, необов’язкові `number`
і `headingLevel` (2–4). Повний матеріал надходить через `fullContent` або
звичайний default slot. Без `pair` весь цей матеріал видимий, нової кнопки немає.

За окремого погодженого opt-in adapter передає `pair`:

```php
[
    'source_key' => $sectionKey,
    'source_revision' => $exactFullContentSha256,
    'main' => $approvedMain,
    'detail' => $unchangedReferencedDetails,
    'detail_references' => $orderedExistingSectionIds,
]
```

Це технічний shape, а не готовий навчальний пакет. `TheorySection::resolve`
не шукає sources, не викликає view за даними БД і не є sanitizer.
Plain string екранується. `Htmlable` дозволений тільки після чинного
безпечного renderer: trusted block HTML та inline HTML мають різні правила;
для inline-полів зберігається `TheoryInlineHtml`. Не позначати довільні
JSON/HTML/назви компонентів як trusted. Не повторювати entity decoding.

Детальні refs мають реально існувати і в повному джерелі, і в detail DOM.
Їхні серіалізовані DOM-піддерева незмінні. Весь текст details відповідає
тексту refs у визначеному порядку; додатковий навчальний текст не вставляється
неявно. IDs не дублюються всередині шару та між main/detail. Вкладені ключі
вправ залишаються нативними disclosures з початковим станом джерела.
Технічний ID summary також зарезервовано: колізія з main/detail IDs
відхиляє пару й повертає повне початкове джерело.

Обидва дозволені шари приходять у початковому server HTML як звичайний DOM.
Кнопка — native `details/summary`; вона лише відкриває вже доставлений текст.
Немає click-only AJAX, template-вставок, spinner чи штучної затримки.
Кожна тема незалежна; canonical не змінюється, нових URL/query режимів немає.
Adapter зберігає чинне рішення course renderer про доступ: section не
отримує додаткових закритих матеріалів і не розширює набір текстів у
гостьовій відповіді. Цей компонент не є перевіркою авторизації. Чинний
course gate може бути UI-контролем над уже доставленим SSR; M25 не
перетворює його на server-side auth і не заявляє про нову гарантію секретності.
Майбутні пакети не повинні додавати detail-поля до гостьового renderer,
якщо чинна політика не дозволяє цьому відвідувачу такий матеріал.

## Безпечна відмова

Відсутня, порожня, невідома або пошкоджена пара, змінена редакція,
неіснуючі/змінені/переставлені refs чи дубль anchor → повний початковий
вміст з caller, без кнопки, без 500 і без тихого обрізання.
`diagnosticCode`/`data-theory-section-fallback` містить лише технічний код
причини, не текст уроку, секрети або персональні дані. Adapter може
збирати цей код у дозволеному діагностичному звіті.

Порожні деталі не виправдовують показ тільки короткого шару: зберігається
повне джерело. Непідтримуваний формат не вважається автоматично готовим.

## Доступність і локалі

UI labels у `theory_blocks.section`: «Докладніше»/«Згорнути» для uk,
відповідні en/pl labels для наявних локалей. Назва контексту summary
екранована; raw heading HTML не потрапляє до атрибутів чи controls.
Існуючі навчальні переклади не генеруються.

Native summary працює Enter/Space/Tab без JS; закритий вміст не є
прихованою tab-пасткою. Без JS є пряме посилання до керування деталями.
Прогресивний `theory-sections.js` відкриває предків цільового fragment,
обробляє hash/Back/Forward, не закриває сусідніх тем. Друк відкриває
детальний шар і повертає його початковий стан після друку.
CSS має враховувати print та reduced-motion; мобільна й desktop версії
отримують той самий текст, а не дві копії контенту.

## Приймання наступного пакета

Перевірити source hashes, ordered текст/пунктуацію/заперечення/числа,
таблиці, refs/href/anchors, відповіді вправ, відсутність duplicate IDs,
SSR обох шарів, no-JS, fragment, клавіатуру, друк, light/dark та course gate.
Не використовувати новий скорочений результат як baseline власного джерела.
Повна сторінка без погодженої пари лишається звичайним підтримуваним режимом.
