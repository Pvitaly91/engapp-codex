# PERF-13 — головна сторінка й повторна побудова manifest курсу

Перевірено 20.11.2026 на локальному Windows / `gramlyze.loc`. Основа робочої гілки `codex/perf-13-home-course-manifest` — `e7b4e0c0c9ec88fa2c014d8b197a03df095b73f4`. Apache фактично обслуговує `D:/DEV/htdocs/gramlyze.loc/public`; його checkout (`41820a2bebdf69004fa7209a2a38457f93efabbd`) містив попередні незакомічені зміни. Знімок A зберіг точні байти чотирьох потрібних PHP-файлів із цього каталогу; їхній текст збігся з основою гілки, а відмінності байтів двох файлів були лише закінченнями рядків. У чинній копії застосовано три цільові файли B, звірено їх SHA-256 до і після HTTP-перевірки. Інші правки, `.env`, конфігурацію Apache, БД, сесії користувача й віддалені сервери не змінювали.

## Що змінилося

- Головна: `HomeController` більше не готує `latestTests`, `featuredCategories`, `recentPages` та `stats`. Перевірено `home.blade.php`, layout, включення, компоненти та можливі спільні дані представлень: ці змінні не читаються. Числа `120+`, `7k+`, `2k+`, `24/7`, текст, картки й посилання залишилися в чинному шаблоні без змін.
- Курси: `show()` передає вже отриманий manifest у `buildCourseStatus()`. Сервіс повторно використовує його лише для того самого нормалізованого slug. Виклик із одним аргументом, перевірки придатності тестів, порядок і доступність уроків залишилися. `PolyglotCourseManifestService`, SQL-вибірку, `questionLinks`, локалізацію, прогрес та кешування не змінювали.

## Дані й HTML

Окремі діагностичні запуски: 12/12 пар A/B пройшли через реальний Laravel kernel у PHP CLI. Обидва варіанти використовували спільні bootstrap, залежності, шаблони й дані локальної MariaDB; варіант цільових файлів звірявся за хешами. Запити працювали в read-only транзакціях, з окремими гостьовими array-сесіями та приватними каталогами скомпільованих шаблонів. У повному HTML замінено лише точне значення фактичного CSRF-токена кожної сесії; порядок посилань і решта HTML збіглися. Структура й вихідні дані view не сортувалися для порівняння.

## Час і пам’ять

PHP 8.5.10, 6 пар на маршрут, порядок A/B, B/A почергово після одного прогону на варіант. Кожен замір — свіжий PHP-процес, прогріті спільні дані БД та окремий прогрітий кеш Blade; час від входу в kernel до отримання HTML, без HTTP і без SQL-логування чи лічильника manifest. CPU — медіана `getrusage()` із дискретністю Windows; пам’ять — медіана пікової активної пам’яті PHP, не розмір зарезервованого блоку процесу.

| --- | ---: | ---: | ---: | ---: |
| `/` | 48,90 / 52,00 / 62,52 | 30,76 / 32,85 / 36,20 | 46,875 → 31,25 | 29,844 → 29,356 |
| `/courses/sentence-builder-english-a1` | 1232,98 / 1302,15 / 1560,58 | 631,77 / 677,93 / 2319,00 | 1179,69 → 625,00 | 85,080 → 84,954 |

У CLI B був швидшим у 6/6 пар для головної і в 5/6 для A1. Діапазони A1 перекриваються: один замір B був повільнішим, його не відкинуто. На машині паралельно виконувався суміжний PHPUnit-набір; причин окремого викиду не встановлювали. Це вимір PHP-шляху, не швидкості повної HTTP-відповіді.

У профілі PHP-CGI Apache перевірка часу змін OPcache ввімкнена (`revalidate_freq=2` с); B перевіряли після цього інтервалу, без перезапуску Apache. Один HTTP-зразок на варіант не дає оцінки розкиду або підстав стверджувати прискорення повної HTTP-відповіді головної чи курсу.

## Перевірки й межі

- Новий SQL-guard на A відхилив 8 запитів, на B пройшов. `PublicHomeSmokeTest` і `CourseSitemapMetadataTest`: 17 тестів, 90 assertions, exit 0; на A і B є наявне попередження PHP 8.5 щодо `PDO::MYSQL_ATTR_SSL_CA`.
- Набір курсів (`PolyglotCourseBlueprintTest`, `PolyglotCourseLandingPageTest`, `PolyglotCourseManifestTest`, `CourseSitemapMetadataTest`, `PolyglotCourseReportCommandTest`): 39 тестів, 500 assertions; 36 пройшли, 3 не пройшли, без помилок виконання та пропусків, exit 1. Невдачі CLI-звіту A1/A2/B1 відтворено на збереженій A із такими самими SQLite fixtures: очікуються застарілі `polyglot-final-drill-a1`, `polyglot-present-perfect-basic-a2`, `polyglot-present-perfect-continuous-basics-b1` замість уже наявних канонічних `sentence-builder-*`. Ці тести й формат CLI-звіту не змінювали. Набори мають 16 спільних sitemap-тестів, тому їх кількості не підсумовуються. Розширений запуск також повідомив 60 попереджень пошуку тестів і одну наявну deprecation PHP.
- Незмінний перевіряльник джерел релізу: 523/523 SHA-256 збіглися в робочій гілці. Навчальні файли й сам перевіряльник не змінювались.
- Браузер: **BLOCKED** — Windows-засіб не зміг підтвердити адресу вікна Opera і зупинив автоматизацію до відкриття тестових сторінок. HTTP і PHP перевірки не зараховано як браузерні.
- Не виконувались підігрів або повтори після таймауту, дослідження історичних Apache-таймаутів чи повторний обхід mixed-адрес. На чинній БД не запускали міграцій, сідів чи імпорту; тестові fixtures створювались окремо. Деплою на Ubuntu/production не було. Приватні квитанції не включені до Git; тимчасових маршрутів або інструментації в застосунку немає.
