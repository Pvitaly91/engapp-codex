# PERF‑15 — пошукові підказки у шапці

Gramlyze, 20.11.2026. Основа `codex/perf-15-site-search-autocomplete` — PERF‑14 (`3653487e246f6da0e497a9178d8332a4f57c76df`), що містить PERF‑13. Локальний Apache обслуговує `D:/DEV/htdocs/gramlyze.loc/public`; шаблон A побайтово збігався з Git. Збережено точний знімок A (`a58fc546ddd724f952cd04ec26eb1a1415b7f44e88e4d3d3f925b761a6bf9f25`).

`resources/views/layouts/catalog-public.blade.php`: спільний `searchBox()` чекає 250 мс після останнього введення. Кожна зміна одразу очищує підказки, скасовує таймер і активний запит та змінює його покоління. Актуальність перевіряється по завершенні `fetch` і `json()`; старий `finally` не очищує новий контролер. HTTP/мережеві/JSON-помилки й непридатний формат залишають список закритим. Escape, submit, видалення компонента та закриття мобільного меню інвалідують роботу. Мобільне `x-show` не знищує компонент — його закриття надсилає окрему подію лише для mobile-пошуку. Enter переходить негайно. Два екземпляри не ділять таймер, номер покоління чи контролер.

Розмітка підказок, підсвічування і його HTML-екранування, формат та порядок результатів, локалізовані URL і серверний `SiteSearchController` не змінені. Нових JS-залежностей, змін SQL, кешу пошуку або навчального пошуку немає. `tests/js/siteSearchAutocomplete.test.js` тестує ту саму inline-реалізацію з Blade, без копії алгоритму.

## Кероване A/B — кількість викликів `fetch`

Однакові вводи та контрольовані відповіді для точного A і B; годинник у мілісекундах від початку, `#n` — номер запиту в цьому варіанті. Тестовий транспорт навмисно доставляв і деякі скасовані відповіді. Реальних мережевих запитів у цьому порівнянні немає.

| Сценарій і послідовність | Виклики A → B | Надіслані фрази, A / B | Застосовані відповіді, A / B |
| --- | ---: | --- | --- |
| Швидко, 90 мс: `pr → pre → pres → prese → presen → present` (0–450) | 6 → 1 | Усі шість / лише `present` на 700 мс | Усі шість / `present#1` на 740. A показував попередню фразу між вводами; B — ні. |
| Повільно, 400 мс: `pr → pres → present` (0/400/800) | 3 → 3 | Усі три / усі три (250/650/1050) | Усі три / усі три. Старі підказки між вводами були лише в A. |
| `pres` на 0, очистити на 90, доставка на 410 | 1 → 0 | `pres` / немає | A застосував `pres#1` і знову відкрив список; B залишив його закритим. |
| Активний запит: `pres` на 0 → `present` на 300, доставка на 420/700 | 2 → 2 | `pres, present` / `pres, present` | A прийняв обидві, зокрема стару, поки чекав нову; B — лише `present#2`. |
| Зворотні відповіді: `pres` на 0 → `present` на 310, спочатку нова на 620, стара на 800 | 2 → 2 | `pres, present` / `pres, present` | A: `present#2` → `pres#1`; B: залишився `present#2`. |
| Повтор фрази `pres → present → pres` (0/320/640), відповіді у порядку #3, #2, #1 (960/1020/1100) | 3 → 3 | Та сама трійка / та сама трійка | A: `pres#3` → `present#2` → `pres#1`; B: лише `pres#3`. |

У B не залишалося результатів попередньої фрази і не було пізнього відкриття. Скорочення HTTP-звернень стосується запитів, які debounce не надіслав. `AbortController` не доводить, що вже надісланий запит припинив виконуватись у PHP чи SQL. Швидкість відкриття сторінок не вимірювали.

- Desktop `uk`: підказки `Present` і `Passive`, підсвічування, очищення поля й Escape; Enter із `  Present & Passive  ` відкрив `/search?q=Present%20%26%20Passive`. Натискання `Advanced Passive Voice` відкриває відповідну локальну сторінку теорії.
- Вузьке вікно: мобільне меню показало підказки; після закриття й повторного відкриття текст `Present` зберігся, старі підказки не повернулися. В `en` і `pl` посилання підказок мали відповідні префікси, Enter в `en` відкрив `/en/search?q=Present`, а перехід за польською підказкою залишив `/pl/` у URL.
