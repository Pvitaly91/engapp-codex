## Вузьке місце й рішення

API `/api/word-search/{lang?}` і вебмаршрут `/words` (також локалізовані `/en/words`, `/pl/words`) викликають `WordSearchController::search`. `/api/search` і пошук матеріалів `/search` — інші маршрути. Пошук має ліміт 10 слів, розпізнає UK/EN/PL, завантажує переклади одним запитом і додає словоформи через третій SELECT. Після початкової перевірки довжини результат контролера має `public, max-age=300, s-maxage=300`; локальний development middleware встановлює `no-store`. Обидві поведінки перевірено окремо.

B пропускає JOIN словоформ, коли **жоден** результат не має одночасно непорожнього типу та заповненого першого перекладу. Якщо такий результат є, повний початковий список перекладів, SQL, групування, порядок і PHP-порівняння дублікатів зберігаються. Не фільтруємо переклади типізованими словами: за числоподібних перекладів це могло б змінити результат `unique()`. Сортування, екранування LIKE, власна форма слова, поля JSON, заголовки та Step-дебаунс PERF‑21 не змінені.

На локальних даних для `english` (UK/PL) і `en` (UK) це **3 → 2 SQL-запити**. Наприклад, UK `en` повертає `10 / 10 / 2` рядки в A, але жодне видиме слово не використовує ці дві форми; B залишає `10 / 10`, JSON збігається. Для UK `go` запит форм потрібен: ті самі `10 / 10 / 3` рядки та словоформи `went`, `gone`.

## Середовище й методика

- Apache обслуговує `D:/DEV/htdocs/gramlyze.loc/public`. Контролер A із цього checkout і Git-база однакові після нормалізації CRLF/LF; SHA‑256 файлу A в обслуговуваній копії `6c35086cf0ce48380315dd98a91baa5b9c47df8cfce09873ede2b2ffee067ab2`. Канонічний LF-файл B, використаний у вимірах: `b179ef3077fb42e58050205bb01cd51cdbf8a5c0fc86f4db7487e8c5627f6e7d`.
- До модифікації контролера зафіксовано A: 23 сценарії, 4 свіжі PHP-процеси й по 6 прогрітих повторів на сценарій у кожному; додатково 69 гостьових GET напряму до Apache. Потім 4 незалежні варіанти мали по 8 повторів у кожному блоці A/B/B/A, з однаковою ротацією сценаріїв. Для точного B також проведено B/A/A/B по 12 повторів на блок і окрему серію з попарним чергуванням усередині кожного сценарію.
- У контрольованих вимірах HTTP обслуговував PHP 8.5.10 `cli-server` лише на `127.0.0.1`, `Host: gramlyze.loc`, зі справжнім Laravel-контролером, конфігурацією з обслуговуваної локальної копії та локальною MariaDB 12.0.2. Приватний стенд перевіряв локальний режим і loopback-конфігурацію MySQL перед підключенням та примусово підтверджував read-only сесію. HTTP-час включає обгортку і Laravel bootstrap, а не тільки контролер; це **не** контрольований A/B Apache. На Apache окремо перевірено фактичний HTTP до/після, без cookies, повторного використання кешу клієнта й вимірів на віддалених сайтах.
- `first-pass` — перший обхід сценаріїв у новому PHP-процесі, не очищений кеш MariaDB. `warm` — повтори після цього обходу. У MariaDB `query_cache_type=OFF`; InnoDB та файловий кеш не очищалися, тож повністю холодну БД не вимірювали. Одноразовий старт PHP входить лише в `first-pass`. Не змішували його з `warm`. Усі варіанти перевіряли однакові дані; відповіді звіряли за HTTP-статусом, типом, кешем, числом байтів та SHA‑256 тіла.
- PHP `hrtime` охоплює тільки контролер, включно з побудовою JSON. SQL ms — події Laravel QueryExecuted (із клієнтськими накладними витратами). Кількість повернених рядків виміряно окремими read-only повторами SELECT; `eloquent.retrieved` — окремим профілем, не в timed runs. Пам'ять — PHP `memory_get_peak_usage()` і приріст від початку контролера. Для грубого Windows-лічильника CPU додатково виміряно по 640 викликів на варіант для чотирьох сценаріїв.

Приватні відтворювані інструменти та результати збережено в `storage/logs/perf-22` (ігнорується Git): `bench.cjs`, `bench.php`, `summarize.cjs`, окремий `rows.jsonl` і `finish.json` для кожної серії. Основні команди: `node storage/logs/perf-22/bench.cjs baseline A 6`, `... compare C2 8`, `... compare B 12 reverse`, `... interleave B 16`, `... profile B`, `... cpu B`. `live A/B` запускається лише коли саме відповідний файл активний на локальному Apache. Не переносити профілювальний сервер на публічний хост.
