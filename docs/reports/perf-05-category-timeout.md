## Що саме могло чекати

Маршрут `theory.category` іде через middleware та прив'язку моделі, потім `PageController::category` читає метадані категорії, локалізує/упорядковує картки й викликає `TheoryPagePromptLinkedTestsService::buildForCategory`. Тут формуються описи пов'язаних тестів за метаданими, визначеннями й рівнями, а не масив питань через `GrammarTestFilterService::questionsFromFilters`. `ComingSoonMiddleware` не запускає тестовий resolver для цього маршруту. Зміна PERF-05 не потрібна для історичної сигнатури, а A/B тут — контроль, не пошук швидшої конфігурації.

У категорії немає `->block()`; глобальне блокування сесій не налаштоване, обидві історичні сесії не мали вхідної Cookie. Це аргумент проти спільного whole-request Laravel lock, не виключення файлового I/O, коротких файлових блокувань чи прибирання файлів сесій. Bootstrap може звертатися до БД; підготовка linked tests може читати cache/визначення; cache miss і SQL wait під час збою не зафіксовані. Статичний шлях не має прямого внутрішнього HTTP-виклику для карток; зовнішнє очікування історично не вимірювалося. `DB::listen` спостерігає завершені SQL, не блокований незавершений запит.

**Остання підтверджена історична межа:** запит потрапив до Apache; його завершальний access-запис має 200 і менший серверний облік тіла, клієнт не зафіксував заголовків або тіла. Поділ затримки між FastCGI/worker, bootstrap, Laravel/SQL/файлами, формуванням відповіді, буферизацією/передаванням та клієнтським harness історично не записано. Сигнатура на різних маршрутах робить спільний серверно-транспортний шлях вартою перевірки гіпотезою, а не встановленою причиною.

## Обмежений локальний контроль

Наперед визначено чотири пари `AB / BA / AB / BA`, послідовно, 2200 мс однакового очікування перед кожним запитом, новий гість без cookies, 60-секундний загальний дедлайн, без автоматичних повторів чи паралельних builds/tests. Один маршрут, той самий locale і контент. У ROOT між руками перемикався лише точний `GrammarTestFilterService.php`; WT і PERF-04 залишалися на B. Файловий SHA не дорівнює доказу виконаного opcode; зонд окремо фіксував, чи був файл узагалі завантажений PHP.

Тимчасовий opt-in probe працював тільки для точного loopback GET `/theory/word-order` із приватним nonce та request ID, без нових маршрутів або зміни конфігурації. Точки: PHP entry, autoload, створення і boot застосунку, middleware, route match, підготовка категорії й linked tests, рендер, response ready/send, terminate/shutdown. На запит — лише кілька записів milestones, PID і агрегати завершених SQL; без SQL тексту/bindings, cookies, відповідей або персонального прогресу. Web/CLI identity порівнювалася приватним HMAC фізичного ROOT і конфігурації локальної БД. Клієнт окремо записував TCP, request finish, TTFB, перше тіло, body end, розмір, статус і відбитки контракту. Перед переходом до наступного запиту вимагали PHP shutdown; на затримці передбачено read-only знімок TCP/PID, а не нові HTTP поверх завислого.
