# PERF‑17 — зв’язки питань лише для вибраного курсу

База — прийнятий PERF‑16, `11a152ca15cfb5db157c00efa707918b76dd3444`. Apache `gramlyze.loc` обслуговує `D:/DEV/htdocs/gramlyze.loc/public`; Git HEAD цього checkout — `41820a2bebdf69004fa7209a2a38457f93efabbd` з уже застосованими локальними файлами попередніх PERF. Точну обслуговувану версію A зафіксовано до зміни (SHA‑256 `ebc333964b20a14d650bfa08fa56ec0c40af86eee61c2c1701811905163e5083`); її Git blob після нормалізації кінців рядків збігався з базою PERF‑16. Checkout не перемикався й не скидався.

- `app/Services/PolyglotCourseManifestService.php`: базові моделі читаються як раніше, але `matchesCourse()` тепер відбирає курс до пакетного `load('questionLinks')`. Зв’язки завантажуються до compose-eligibility та `map()`. Порожня Eloquent-колекція не читає links.
- Поля, порядок за `lesson_order`/slug, правила eligibility, URL і локалі не змінені. `question_count` і далі рахує рядки зв’язку з урахуванням повторів; relation зберігає сортування за `position`. Сервіс не додає кешу, SQL-фільтра за JSON, нових залежностей або схеми. `sitemapEntryMetadata()` і PERF‑16 не змінено.

## Точність

В ізольованій SQLite `:memory:` усі 21 повні manifest A/B збіглися побайтово: A1, A2 і B1 × canonical/legacy × `uk/en/pl`, порожній slug, відсутній курс і курс без придатного уроку. У fixtures були filters масивом і JSON-рядком, сторонні курси, точне порівняння регістру й обрізання пробілів, обидва джерела compose-eligibility, порожні й дубльовані зв’язки, однакові `lesson_order`, попередній і наступний урок.

Цільовий контроль запиту довів один batch, який охоплює всіх кандидатів (навіть пізніше відхилених за eligibility), та жодного читання links без кандидатів. На точній A ці нові перевірки відтворили обидві старі проблеми; решта перевірок семантики пройшла.

`tests/Feature/PolyglotCourseManifestTest.php`: 5 цільових тестів, 69 перевірок. Разом із landing A1/A2/B1, blueprint, регресією PERF‑13 «один build», чотирма контекстами compose-вправ, прогресом PERF‑16 і admin debug: 45 тестів, 1 211 перевірок, exit 0. Залишилося наявне попередження PHP 8.5 про застарілий атрибут PDO; збоїв немає.

## Профіль читання

Локальна MariaDB 12.0.2 на loopback, з чинним набором даних `.loc`, у read-only snapshots. Окремо від замірів часу перевірено SQL, кількість отриманих рядків незалежним підрахунком і Eloquent-моделі, створені для них. На маршруті вправи запит для самого уроку відділено від запиту manifest.

| Сценарій | Базові моделі A → B | Кандидати / ID у batch B | Рядки links = моделі A → B | SQL manifest A → B | SQL маршруту A → B |
| --- | ---: | --- | ---: | ---: | ---: |
| A1 (uk/en/pl), також manifest вправи A1 | 750 → 750 | 16 / 12–27 | 44 584 → 480 | 2 → 2 | Сторінка 2 → 2; вправа 16 → 16 |
| A2 | 750 → 750 | 16 / 1–11, 28, 96–99 | 44 584 → 384 | 2 → 2 | 2 → 2 |
| B1 | 750 → 750 | 16 / 100–115 | 44 584 → 576 | 2 → 2 | 2 → 2 |
| Відсутній курс | 750 → 750 | 0 / без batch | 44 584 → 0 | 2 → 1 | — |

У A batch охоплював ID усіх 750 базових тестів. Два SQL manifest — базовий SELECT і один SELECT links за `saved_grammar_test_id IN (…)`, впорядкований за `position`. Вправі також потрібен окремий незмінений SELECT її links: 72 рядки для тесту 12. Набори власних рядків і їхній порядок усередині кожного уроку збережені. Нових запитів на кожен урок немає.

На MariaDB повні manifest для трьох курсів × трьох локалей × двох входів, а також порожнього та відсутнього курсу, збіглися побайтово. Дані контролерів семи HTTP 200 відповідей (A1, A2, B1, A1 en/pl, legacy A1 і вправа) збіглися точно; HTML збігся після заміни лише трьох входжень адреси Livewire, що залежить від ключа приватного тестового застосунку. Це відповіді HTTP kernel, а не Apache.

## Чистий час і пам’ять

PHP CLI 8.5.10, реальний Laravel HTTP kernel, гостьовий стан, однаковий прогрів A/B, без SQL-логування чи інших власних перевірок під час серії. Таймер охоплював `handle` + `terminate`, без старту PHP, підключення PDO та підготовки застосунку. Парні запуски чергувалися AB/BA.
