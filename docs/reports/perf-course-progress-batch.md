# PERF‑16 — пакетна підготовка прогресу курсу

Gramlyze, 20.11.2026. База A — прийнята гілка PERF‑15, `6e42ed3b83b8b1a266d2721a7a6290b01ce412ce`. Apache для `gramlyze.loc` обслуговує `D:/DEV/htdocs/gramlyze.loc/public`. Версія A сервісу в робочій гілці й на диску обслуговуваної копії була побайтово однаковою: SHA‑256 `fc7f401145cbc591c0cd3626e1d31669d48300daab8ecb3f90016894dc6036be`.

- `app/Services/PolyglotProgressService.php`: побудова серверного прогресу авторизованого користувача готує агрегати лише для точних уроків поточного курсу з наявним рядком прогресу. SQL-підрахунок групується за ID рядка прогресу й окремо враховує правильні спроби без UUID. Повна історія з UUID читається потрібними полями, порціями до 1000 рядків за `answered_at, id`. Ключі, порядок і часові мітки статистики формуються в PHP, а зіставлення slug для SQL зберігає правила порівняння БД. Використовується наявна перевірка доступності таблиць.
- Агрегати готуються заново для кожного payload на тій самій connection; постійного кешу немає. Manifest, запис та імпорт спроб, перерахунок останніх 100 оцінок і правила проходження не переписані. Маршрути, клієнтський контракт і схема БД не змінені.
- `tests/Feature/PolyglotUserProgressTest.php`: додані перевірки точного порядку й типів статистики, меж вибірки, порогу 4.50, SQL та перевірок схеми, пагінації з однаковим часом, повторного читання в транзакції, імпорту, повторного UUID, debug і недоступної таблиці.

## Точність та SQL

Ізольований HTTP kernel Laravel через PHP CLI 8.5.10 (SQLite 3.53.4 `:memory:`), без Apache, зовнішніх HTTP-запитів, реальної авторизації чи особистих даних. GET і POST пройшли штатні маршрути та контролер з авторизованим тестовим користувачем. Для кожного плеча — новий процес і заново підготовлена БД, спільний фіксований час. Профіль SQL проведено окремо від замірів часу.

У 13 сценаріях усі 20 JSON-відповідей A/B збіглися побайтово, включно з порядком ключів, типами і датами. Перевірено порожній, один і кілька рядків прогресу, прогрес із нульовим лічильником, зайві спроби без прогресу та за межами користувача/курсу/уроків, поріг 4.50 і `true` при нижчій оцінці, різний регістр та пробіли в UUID, рівні дати, гостьовий і fallback-режими. POST побачив новий запис до commit транзакції; повтор того ж UUID не створив другого запису. Один екземпляр сервісу до й після запису повернув актуальні агрегати. Імпортовані правильні спроби без UUID збільшили `correct_attempts`, не додаючи елементів у `question_stats`; debug зберіг попередній результат.

| Операція | SELECT спроб A → B | Перевірки схеми A → B | SELECT progress | Manifest | Записи: спроби + progress | Усього SQL A → B |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| GET: 0 уроків із progress | 0 → 0 | 2 → 2 | 1 | 2 | 0 | 5 → 5 |
| GET: 1 урок | 2 → 2 | 4 → 2 | 1 | 2 | 0 | 9 → 7 |
| GET: 8 уроків | 16 → 2 | 18 → 2 | 1 | 2 | 0 | 37 → 7 |
| POST: 0 або 1 урок до запису | 6 → 6 | 6 → 4 | 2 | 4 | 1 + 1 | 20 → 18 |

У профілі A за кожен урок виконав окремий `COUNT(*)` і SELECT з `WHERE lesson_slug = ?`. У B за весь набір виконано `COUNT(*) … GROUP BY progress.id` і читання `ORDER BY attempts.answered_at, attempts.id LIMIT 1000`, обидва з `JOIN` за користувачем, курсом та slug уроку і з `WHERE progress.id IN (…)`. Під час POST до SELECT спроб також входять незмінені читання для запису й перерахунку.

Звичайний набір: 12 уроків у manifest, 8 з progress, 392 спроби в межах вибірки, 100 унікальних пар «урок + UUID» у статистиці. Довга історія: 32 008 спроб і 324 пари на тих самих 8 уроках; ще по 4 спроби поза вибіркою в обох наборах. На довгій історії читань стало більше через ліміт порції; обробка не обрізає історію до останніх 100. Це вимір SQLite, а не профіль SQL драйвера MariaDB.

## Час і пікова пам’ять

По 6 пар для GET і POST у порядку AB/BA, без SQL-логування, PHPUnit і збірки. Час: обробка й завершення запиту Laravel, без старту процесу, bootstrap та підготовки даних. PHP-пік — активна пам’ять (`memory_get_peak_usage(false)`), скидання піку після підготовки fixture. POST у кожному запуску додавав ту саму одну нову спробу до відновленого набору.
