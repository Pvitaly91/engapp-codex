# Gramlyze — комплект прийнятих PERF

[Ручне перенесення й відкат](gramlyze-perf-release-deploy.md) · [Матриця фактичних локальних маршрутів](gramlyze-perf-release-coverage.csv) · [SHA-256 runtime-входів](../../tests/Fixtures/perf-release-sha256.v1.json)

Цей пакет зібрано окремо від активного `gramlyze.loc`. База інтеграції — `origin/main` на `8b4d52b003f7f827b6a584f54fa28eb6934d14ab`; чотири незалежні службові placeholders з main збережено. Прийнятий versioned checkpoint — `9ab9ee1ea8dc17ac4cbd2bc8c80618a691c1f340`, у ньому вже є PERF-01–06 і 10. Точні незакомічені пізніші runtime-входи були звірені окремо з прийнятою локальною копією. Чужі локальні зміни та приватні артефакти залишено на місці.

## Що працює у спільному коді

| Оптимізація | Умова входу | Межа дії |
| --- | --- | --- |
| PERF-01/02 | Кешоване меню каталогу: SSR desktop, закріплений lazy mobile; генерація тільки явною командою, перевірка mode/locale/revision | Індекс, категорії та уроки, коли є сумісний snapshot. M42 memo — лише в межах запиту, зі збереженим першим integrity check |
| PERF-03 | Finite catalog dispatch і точний відбір власних даних; контроль кількості варіантів у відповідних пакетах | Спільні входи каталогу та тематичного mixed, коли підходить ідентичність пакета; не глобальна зміна добору |
| PERF-04 | `TheoryPracticeCompactProjection`: перевірка SHA, далі ранній відсів чужого, повна валідація власного | Віджети практики уроку; не загальна межа довжини тексту |
| PERF-05 | `GrammarTestFilterService`: готовий набір не готує невикористані довідники | Тести зі спільним шляхом добору; конструктор зберігає повний `prepare()` |
| PERF-06 | `TestJsV2Controller` та `MarkerTheoryMatcherService` читають marker tags для готового набору пакетом; відновлення не перечитує їх без потреби | Спільний шлях підготовки JS-тесту, коли використовуються marker tags |
| PERF-10 та PERF-12 B | Вхід практики з відомими UUID/ID; для відхилення потрібна підтверджена точна чужа пара | Conditionals, Reported Speech, Clauses/Linking, Common Mistakes; непідтверджена або власна пара зберігає старі захисні перевірки |
| Passive і два лексичні пакети | Аналогічний точний gate; лексичні пакети додатково звіряють UUID питання й seeder | Passive Voice, Pronouns & Demonstratives, Nouns, Articles & Quantity, тільки відповідні пакети |

Належність визначає спільний код і versioned реєстри, а не whitelist URL Word Order/PPC. Однаковий HTML без справжнього probe виконання не є доказом відсутності fallback; тому докази runtime-входів, поведінки гілок і парності рендеру обліковуються окремо. Відхилені PERF-07/08 та універсальний JSON-кеш не активовані; точний `TheoryNativeContentRelease.php` відповідає SHA `23b89050f061faddd80debce2fefc8dd356a0b49dffa44f79b2200cb5cbbef11`. Історичні заміри залишено у [PERF-01–03](perf-01-03-delivery.md), [PERF-04–05](perf-04-05-delivery.md) та [PERF-06/10](perf-06-10-delivery.md); ці показники не сумуються і не екстраполюються на сервер.

## Відтворення та межі перенесення

- PHP 8.5.10, Composer із lock — 122 залежності, без оновлень чи видалень; власний оптимізований release autoload (9941 клас; 1415 відомих попереджень PSR-4 для старих сідерів); production platform check — exit 0.
- Node 22.15.0: `npm ci --offline` — 192 пакети; Vite 5.4.19 — 57 модулів, чотири assets і manifest, exit 0. Composer і npm lock-файли не змінилися.
- 523 SHA-256 фізичних файлів, Git blobs та повторного export із `core.autocrlf=true` перевірено; правила `.gitattributes` точкові, очікувані хеші не змінено. У пакеті є frozen JSON, контракти, реєстри, definitions та всі versioned build-входи; згенерований frontend, встановлені залежності, меню, приватні логи/дампи, тестові БД не публікуються. Вихідні обслуговувані файли, контентна БД, прогрес і `main` не змінювалися.
- `theory:menu-build` та `theory:menu-build --check` завершилися з exit 0 на окремому release menu store для `en`, `uk`, `pl`; конфігурація активного вебсайту не змінювалася. Production menu check належить повторити перед активацією на фактичному серверному профілі.

## Приймання

Інвентаризація фактичних маршрутів і view data: 254 опубліковані уроки, 41 категорія, 668 різних mixed-шляхів; `en`, `uk`, `pl`. У development-профілі це **2 388 адрес**: 762 уроки, 123 категорії, 3 індекси й 1 500 mixed. Ще 762 пов'язані адреси не є mixed і не входять у цю матрицю. Це різні адреси, а не різні навчальні матеріали. Production-профіль перевіряється ізольованими локальними тестами; мережевий продакшн не викликався.

Парний рендер викликає реальний Laravel kernel з власним Composer autoload кожної копії. Підключення — до однієї перевіреної loopback-БД; кожен процес має окрему консистентну read-only транзакцію, сховище/сесія ізольовані. Сайт не отримує мережевого HTTP. Контракт включає головний навчальний HTML, уроки/посилання, дані вбудованих вправ, позначки native й fallback, версію меню. Для mixed порівнюються добір, порядок питань, відповіді, підказки й склад варіантів, зі збереженням та відновленням окремої гостьової спроби там, де це входило до проби.

Буквальне порівняння основного та повного HTML збережене окремо. Для фактичної парності основного HTML дозволені лише CRLF→LF і звірені мітки часу для восьми точних статичних JS: `english-answer-variants.js`, `authored-practice-ui.js` та `m39/m40/m41/m43/m44/m45-practice-ui.js`. Для кожного включення потрібні той самий URL/файл, відповідність фактичному `filemtime` цієї копії та точний спільний SHA-256 фізичних байтів; інший URL чи довільне значення не нормалізується. Цю різницю підтверджено на ізольованих знімках уроків Present Simple Passive і Future Continuous vs Future Perfect Continuous. У повному HTML контрольної категорії додатково видно відмінні версії CSS та статичних JS. Свіжий публічний CSS проти наявного відрізняється одним доданим правилом `.invisible`; Vite JS збігається. Побайтовий збіг повного HTML і візуальну відповідність не заявляємо. Початкові строгі невідповідності та повтори з окремими критеріями не перезаписані.

### Результати маршрутів

Порівняли 966 адрес, зокрема **всі** індекси, категорії та уроки в трьох локалях. Усі 885 рендерів уроків і категорій показали фактичний menu hit в обох копіях. Видимі native markers є на 718 адресах уроків і 78 адресах категорій у кожній копії; єдиний зафіксований `invalid-native-data` на `/pl/theory/verb-patterns/stop-remember-forget-try-regret` однаковий у базі й релізі. Це не доказ, що кожен допустимий пакет віджета активний на кожному уроці; caller gates додатково перевірено за точними frozen fixtures у PHP.

Mixed перевірено вибіркою: 60 тематичних адрес (є приклад з кожної з 41 категорії українською і контрольні уроки в `en`/`pl`) плюс 18 динамічних Word Order A1–C2 у трьох локалях. **75 із 78** ізольованих серверних спроб пройшли профіль resume/reset в обох копіях, незалежно від збігу двох свіжих наборів. Суворі 22 FAIL не прибрано з матриці:

- **18** динамічних: для кожного рівня і локалі працюють гостьові resume/reset, але незалежні свіжі набори різняться. Контроль тієї самої бази для EN A1 з однаковим охопленням і фільтрами теж повернув 32/32 питань із різними порядком/складом і відповідними даними. Штатний `Randomizer` не підміняли; незалежні свіжі спроби не підтверджують побайтову парність.
- **2** локалізації Present Simple Passive (`en`, `pl`): збережено відповідь, позицію, кількість спроб, порядок, відповіді й підказки. У кожній із двох копій після resume змінився склад варіантів. Reset у цих невдалих суворих пробах не зараховано.
- **1** `/test/past-perfect/forms`: в обох копіях відновилися відповідь, позиція й кількість спроб, але змінилися підказки; reset після цього суворого незбігу не зараховано.
- **1** `/test/tenses/past-perfect-vs-past-perfect-continuous`: порядок і підказки між свіжими спробами збіглися, а варіанти, контент і відповіді — ні. Той самий розподіл відмінностей отримано між двома свіжими спробами тієї самої бази з 84/84 питаннями, а resume/reset пройшли в обох копіях.

Для інших mixed-адрес є доказ їхньої наявності та шляху реєстрації, не повний рендер. `NOT RUN` не зараховано як PASS. Пакет готовий до перевірки й перенесення; всеохопне mixed та браузерне приймання не завершено.
