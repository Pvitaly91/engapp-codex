## Доставка меню

Обидві гілки залишають ту саму команду, schema, HTML-дерево й revision.
A повертає готовий desktop HTML у документі; B отримує його через окремий
revision-pinned GET. Mobile і mixed — контрольні випадки. Перші гостьові
відвідини — нові cookie jars; вони не скидають OPcache/Blade і не є
імітацією рестарту сервера. Warm — один гостьовий cookie jar на ціль,
послідовні A/B/B/A, без прикладного профілювання. Harness не повторює
невдалі запити й зберігає всі спроби. Сесійні дані й навчальний банк не
переписуються для стабілізації: сирі рядки містять IDs і SHA наборів.

На двох уроках B зменшує документ рівно на 297 220 B (290,25 KiB).
Окремий desktop body — 298 094 B, тому повна перша передача в B більша на
874 B без урахування заголовків. Зафіксовані тіла відповідей — identity,
поза HTTP-заголовками/фреймами. За обох варіантів TTFB і total різняться
ліченими мілісекундами на loopback. +297 220 B у документі не пояснюють
історичний стрибок повного часу на 1–2 секунди.

переданого payload практики та IDs запитань у тому самому порядку. Paired

У категорії всі 20 пар також повернули однаковий desktop fragment;
у документі категорії немає набору завдань для порівняння. Поточні

Це не A/B із динамічним деревом старого checkout, тому історичний
стрибок не можна причинно приписати жодній конкретній зміні.

У всіх п'яти цілей — 20/20 warm для A і 20/20 для B; невдалих
контрактів не було. Mixed: 20/20 однакових пар повних question payloads
та впорядкованих IDs. Mobile: однакова revision, розмір та відбиток body.
Сира серія: `delivery-inline-v-deferred-2026-11-09T21-15-52-046Z-d04667e7.jsonl`;
агрегат поруч у `.json` (TTFB, перший chunk, total, p95, bytes, залежні
запити, перші гостьові відвідини). Окреме читання desktop snapshots не
дало виграшу для повних сторінок, тому залишено inline. Endpoint і
мобільний versioned fetch залишаються.

## Окремий серверний експеримент

Кандидат — повторно використовувати лише вже перевірені незмінні
`sourceTargets` і `load` M42 в межах одного запиту до theory lesson/category.
Ключ містить тип артефакту, source root і pinned revisions. Перший доступ
виконує попередню перевірку байтів, source signature та exact semantic
comparison; помилка не кешується. Кожний новий запит і кожний explicit-root
виклик знову проходить попередні перевірки. Немає змін до перевірки окремих
блоків, питань, джерел чи записів у БД. Курси та mixed-маршрути не отримують
цей request memo. Для незалежного порівняння обидві руки мають inline-меню.

Додатковий профіль із контрольним перемикачем (Word Order A/B/B/A,
PPC A/B) підтвердив саме повторну перевірку однакових байтів. Повні
результати — `m42-lesson-memo-profile-2026-11-09T21-30-22-678Z-b4d86d33.jsonl`.
Мітки `m42-load` і `m42-source-signature` можуть вкладатися; їхні
тривалості не підсумовуються. Рендеринг включає ці виклики.

Парні selection digests були ідентичні. Залишилися перевірки release,
підготовка карток і рендеринг; зменшення не означає, що вартість усієї
теорії або mixed-тестів усунено. У профілі категорії цей M42 етап не
спостерігався, а для standalone mixed він поза межами оптимізації.

Перевірка інших кандидатів за поточним кодом: `questionsFromFilters()`
досі викликає `prepare()` і повертає лише questions; `prepare()` готує

питання після `get()` із eager-loaded answers/options/verb hints, тоді як
пізніше `loadQuestions()` додає відсутні relations пакетно. Окремі
`getAllMarkerTags()` і умовний legacy TextBlock lookup на питання
залишаються. Це наявні шляхи коду, не виміряні самостійні причини.
Вони не змінені, щоб не змішувати виправлення та не ризикувати добором.

## Браузерне приймання

Окремі точкові вимірювання в IAB, не частина HTTP-серій. Для desktop
порівняння M42 у двох варіантах був у baseline; браузерний зонд додавав
приблизно 11 КБ до документа. TTFB, response body і transfer size — із
Navigation/Resource Timing; готовність зчитувалася з DOM із кроком 50 мс.

речень, не тільки сирий шаблон. LCP/CLS — на момент спостереження, до вводу
там, де зонд його зафіксував. По одному зразку не доводять зміни CLS.

переходу на canonical URL відкрилися варіанти, sidebar відсутній;

Фінальний браузерний повтор після видалення зонда мав таймаут
керування вкладкою; фінальну чисту збірку перевірено HTTP та тестами нижче.
Окремого live admin-профілю та браузерного режиму без JavaScript не було.
Ці сценарії не позначено як PASS. No-JS fallback і перевірки production-mode
покриті ізольованими тестами/статичним контрактом, не production-запитами.

## Фінальний стан та перевірки

- Фінальний HTTP: обидва уроки, категорія, mixed і menu fragment — **200**.
  Уроки: один desktop snapshot inline і конструктор речень; категорія:
  inline snapshot; mixed: dataset без sidebar. Початкові HTML bodies —
  606 958 / 564 389 / 394 044 / 837 199 B відповідно. Діагностичних
  headers, атрибутів зонда й експериментальної доставки у відповіді немає.
- Mobile endpoint: 258 211 B; revision і ETag SHA-256 збігаються.
  `If-None-Match` повернув 304 / 0 B, невідома revision — 404.
- `theory:menu-build --check --locale=uk` → `--locale=uk` → повторний
  `--check`: усі успішні, build повернув `unchanged`.
  UK revision лишилася
  `45d9688239f51e117650842a619b42c6a47f6d5a5414ff35b4b8de97343eae1a`
  (41 категорія, 254 уроки). Fresh build, publication/rollback, locale
  isolation і production-mode контракти — у тестах з окремими fixtures.
- PHP: **28 тестів, 799 assertions, 0 failures**, ізольована SQLite.
  У складі всі 25 перевірок меню з попереднього звіту та 3 нові сценарії M42:
  змінений native map, змінений M27 source і транзитивна перевірка M27
  у native map. Поза theory, за явного root і в новому запиті змінені
  байти відхиляються; всередині одного theory request повторно
  використовується вже перевірений незмінний результат.
  PHPUnit вивів один deprecation (такий клас зауваження вже був у
  PERF-MENU-01); цей запуск не виводив його деталі.
- JS: **19/19** — 12 перевірок меню/пошуку (Node), 7 геометрії (Vitest).
  Покрито BFCache, один mount, активні гілки, пошук, mobile pinned fetch,
  fallback і повторне відкриття.
- Історичні pins не переписувалися: для старого M84 source-boundary
  перевірено, що SHA контролера вже у pre-PERF-02 served preimage не
  відповідає жодному з історичних профілів. Цей окремий історичний
  набір не входить у заявлені 28 тестів. Сирий validator
  `TheoryNativeContentRelease.php` відновлено байт у байт.
